# 05 复盘

## 最难的问题

1. **「硬性要求不可擅自改」的边界如何保证**
   prompt 无法 100% 约束模型，单靠提示词存在越权风险（题目明确「越权发布 = 关键缺陷」）。
   解法：区分硬性/软性要求（`hard_constraint` 字段），并在 Agent 层加**后置校验护栏**，
   对 Mock 与真实 LLM 统一兜底拦截，配两个单元测试证明拦截生效。

2. **「保存失败」的自然触发**
   若 faulty 在查询时即暴露，决策器会直接绕开、走不到 save 阶段。解法：把 faulty 设计为
   **隐藏故障**——查询时 `status=free`、保存时才抛错，才真正走完「查时段→决定保存→保存失败」链路。

3. **重复提交的幂等键选择**
   用内容 hash 会让「同时段微调描述」误判为新草稿；改为 `(asset_id, slot)` 最无歧义，
   且与「同一素材同一时段只一份草稿」的业务语义一致。

## 学习收获

- ReAct 的「动态决策」不等于堆分支：关键是**动作选择由工具返回驱动**，Mock 状态机
  与真实 LLM 共用同一 `Action` 结构，才能无缝替换。
- 护栏（guardrail）是 LLM Agent 的工程刚需：把不可妥协的业务约束从「提示词期望」
  升级为「代码级断言」。
- 多厂商 LLM 用 OpenAI 兼容协议统一接入，能用一个 client 覆盖 DeepSeek/Qwen/Claude，
  大幅降低接入成本。
