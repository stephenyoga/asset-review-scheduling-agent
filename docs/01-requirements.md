# 01 需求说明

## 用户与目标

- **用户**：内容团队运营人员。
- **目标**：从素材库中找出「待处理」素材，形成**无冲突、可确认**的发布排期。

## 输入与材料

| 输入 | 说明 |
|---|---|
| 素材 ID、元数据 | 标题、分类、负责人、时长、风险标记、发布时间要求 |
| 已有排期 | 日期 + 时段占用状态（free / occupied / faulty） |
| 审核规则 | 风险规则（违禁分类、违禁词、时长超限） |

## 交付结果（每项素材）

- 审核状态（approved / blocked / need_more_info / pending_confirmation）
- 风险原因
- 建议时段
- 待确认项
- 草稿保存状态（drafted / save_failed / none）

## 范围与硬边界

- **只保存草稿**，绝不接真实发布（不出现 `published` 状态）。
- **未经用户同意，不得擅自改变硬性发布要求**（`hard_constraint=true` 或存在 `hard_deadline`）。

## 成功标准（6 个验收点）

1. **正常排期**：无风险 + 时段空闲 → 保存草稿。
2. **素材信息缺失**：必填字段缺失 → `need_more_info`，不排期。
3. **规则风险**：高风险 → `blocked` + 风险原因。
4. **时段冲突**：软性 → 建议替代时段 + 待确认；硬性 → 阻断 + 请求确认，不擅自改。
5. **重复提交**：相同 `(asset_id, slot)` 重复保存只产生一份草稿。
6. **保存失败**：明确返回失败，绝不虚报成功。

## 非目标（题目明确非必需）

- 图形界面、线上部署、多 Agent 协作、生产级 Runtime。
- 真实发布动作、时段容量校验（`duration_min` 仅作展示）。
